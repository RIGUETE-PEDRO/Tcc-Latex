\subsection{Trabalhos correlatos}

Os trabalhos correlatos permitem observar como problemas semelhantes foram tratados em outros contextos e quais lacunas permanecem em relação à proposta deste projeto.

\subsubsection{Sistema de Point of Sale em cafeteria}

\citeonline{hidayat2023} desenvolveram um sistema de informação POS para uma cafeteria, utilizando Laravel, PHP, MySQL e o padrão MVC. O estudo informa que registros manuais de relatórios e estoque podiam gerar demora, perda de documentos e erros de cadastro. A solução foi projetada com método waterfall e diagramas como atividade, contexto, caso de uso e fluxograma.

A proximidade com este trabalho está no uso de Laravel, MySQL e no foco em ambiente de venda de alimentos e bebidas. A diferença principal está na proposta deste projeto de enfatizar também comandas, RBAC e organização operacional integrada.

\subsubsection{Restaurant Management System}

\citeonline{jingga2014} propuseram um modelo de Restaurant Management System desenvolvido com PHP e MySQL. O sistema buscava apoiar a comunicação entre garçom, chef e caixa em tempo real, além de contemplar processos ligados a pedidos e pagamentos.

Esse trabalho é relevante por tratar diretamente de restaurantes e por reconhecer a importância da integração entre atendimento e preparação. Contudo, a proposta aqui apresentada adota Laravel, Docker e controle de acesso baseado em papéis, além de direcionar a solução para lanchonetes de pequeno porte.

\subsubsection{POS web com Laravel para Meetup Station}

\citeonline{khairunnisa2022} desenvolveram um sistema POS web para a UMKM Meetup Station, negócio do setor de alimentos e bebidas. Segundo o estudo, a empresa realizava registros de transações em livro físico e cálculos manuais, o que causava erros. A solução utilizou Laravel, PHP, PostgreSQL e metodologia waterfall.

Os testes indicaram validação funcional completa e funcionamento responsivo em diferentes navegadores e resoluções. A principal contribuição para este projeto é a demonstração de viabilidade de uma solução web para pequenos negócios alimentícios. Como diferença, o sistema proposto neste trabalho utilizará MySQL e dará maior ênfase a estoque, comandas e RBAC.

\subsubsection{POS multipagamento para UMKM Mr. Boba}

\citeonline{lathief2023} apresentaram um sistema POS multipagamento baseado em Laravel para a UMKM Mr. Boba. O estudo relata dificuldades com vendas manuais, ausência de alternativas de pagamento não presencial e demora no fechamento de relatórios. O desenvolvimento adotou o método RAD e testes black-box.

Esse trabalho contribui por evidenciar a importância de relatórios computadorizados e de maior agilidade no atendimento. A proposta deste projeto, entretanto, não se concentra em múltiplos meios de pagamento, mas na gestão operacional integrada da lanchonete.

\subsubsection{Sistema de caixa web para Natta Coffee}

\citeonline{rusmara2025} desenvolveu um sistema de caixa web para a Natta Coffee com framework Laravel, visando melhorar transações de venda, controle de estoque e relatórios financeiros. O estudo adotou RAD e indicou ganhos na precisão de registros, velocidade de pagamento e emissão de relatórios.

A relação com este trabalho é direta, pois ambos tratam de estabelecimentos de alimentação e de sistemas web com Laravel. A diferença está na ampliação proposta para controle de comandas, perfis de usuário e estrutura de permissões.

\section{MySQL}

De acordo com \citeonline{milani2007}, o cenário de globalização e o avanço da automação, impulsionados pela popularização da internet, tornaram o armazenamento de dados um passo primordial para a migração de negócios para o ambiente digital. Nesse contexto, o MySQL surge para suprir essa demanda de organização de informações.

O MySQL é um Sistema Gerenciador de Banco de Dados (SGBD) relacional distribuído sob um modelo de licenciamento duplo, que inclui uma versão de código aberto. Embora tenha sido projetado inicialmente para aplicações de pequeno e médio porte, a ferramenta evoluiu para atender também a projetos de maior escala. Segundo \citeonline{milani2007}, o MySQL apresenta robustez e recursos comparáveis aos de sistemas proprietários, como SQL Server e Oracle.

\section{PHP}
Conforme afirma \citeonline{DallOglio2015}, o PHP — que originalmente significava Personal Home Page — é uma linguagem de programação criada por Rasmus Lerdorf no outono de 1994. Inicialmente, a ferramenta consistia em um conjunto de scripts escritos em linguagem C, destinados à criação de páginas dinâmicas para que o autor monitorasse o acesso ao seu currículo na internet. Com o aumento da popularidade entre outros usuários, Lerdorf adicionou novos recursos, como a interação com bancos de dados. Em 1995, o código-fonte foi liberado, permitindo a colaboração de novos desenvolvedores. Vale ressaltar que, durante um curto período, a linguagem também foi denominada FI (Forms Interpreter).
\section{Laravel}

De acordo com \citeonline{Laravel2025}, o Laravel é um \textit{framework} para o desenvolvimento de aplicações web em PHP. A ferramenta oferece recursos para tarefas recorrentes, como roteamento, acesso a bancos de dados, autenticação e organização da aplicação, podendo ser utilizada tanto no desenvolvimento do \textit{back-end} quanto em aplicações completas.

\section{Git}
Segundo \citeonline{Ferreira2014}, o Git é um sistema de controle de versão que permite registrar e acompanhar as alterações realizadas no código-fonte ao longo do desenvolvimento.

Seu fundador, Linus Torvalds, criador do sistema operacional Linux, estava descontente com o BitKeeper, o sistema para controle de versão no desenvolvimento do kernel Linux. O Git também é bastante utilizado em empresas em todo o mundo, inclusive no Brasil.

O uso dessa tecnologia favorece a rastreabilidade das modificações e a colaboração entre desenvolvedores.

\section{GitHub}
Conforme afirma \citeonline{Ferreira2014}, o GitHub foi criado em 2008 como uma aplicação web para hospedagem de repositórios Git e colaboração entre desenvolvedores.

Diversos projetos de código aberto importantes são hospedados no GitHub, como jQuery, Node.js, Ruby on Rails, Jenkins, Spring, JUnit e muitos outros.

Atualmente, o GitHub se tornou uma das principais plataformas utilizadas por desenvolvedores e empresas para compartilhamento de código, controle de versões e colaboração em projetos de software.

\section{Blade (Sistema de Templates)}

Conforme \citeonline{blade2016}, grande parte dos frameworks web utiliza sistemas de templates para padronizar a interface visual das aplicações. Esse recurso otimiza a construção do projeto, facilitando o reuso de código e centralizando partes fixas da interface.

Com esse objetivo, o Laravel utiliza o Blade, um sistema de templates que se diferencia de outras soluções em PHP por não restringir o uso da linguagem PHP em suas páginas. Além disso, no Blade, cada view é compilada e armazenada em cache até sofrer alguma alteração, o que torna a aplicação mais eficiente e leve.

\section{Visual Studio Code}
O Visual Studio Code é um editor de código-fonte desenvolvido pela Microsoft, amplamente utilizado no desenvolvimento de software. Ele oferece suporte a múltiplas linguagens de programação, integração com Git e extensões que aumentam sua funcionalidade \citeonline{vscode2026}.

Devido à sua leveza e flexibilidade, tornou-se uma das ferramentas mais populares entre desenvolvedores web e back-end.

\section{Controle de Acesso Baseado em Funções (RBAC)}

O modelo de Controle de Acesso Baseado em Funções, conhecido pela sigla RBAC (\textit{Role-Based Access Control}), é um método de autorização que gerencia o acesso de usuários a sistemas, aplicações e dados com base em funções predefinidas. Segundo \citeonline{ibm_rbac}, nesse modelo, o acesso não é atribuído diretamente ao indivíduo, mas ao papel que ele desempenha na organização.



Em um sistema que utiliza RBAC, um administrador atribui a cada usuário uma ou mais funções, em que cada função representa um conjunto específico de permissões ou privilégios. De acordo com \citeonline{ibm_rbac}, esse modelo oferece diversas vantagens:
\begin{itemize}
    \item \textbf{Simplificação da gestão:} facilita o gerenciamento de acesso em organizações com muitos funcionários;
    \item \textbf{Segurança da informação:} auxilia na proteção contra ações internas indevidas e ameaças externas;
    \item \textbf{Princípio do menor privilégio:} garante que o usuário tenha acesso apenas aos recursos necessários ao exercício de sua função.
\end{itemize}

A aplicação do RBAC é fundamental para manter a integridade dos dados e a organização dos fluxos operacionais, permitindo que o sistema escale de forma segura à medida que novos perfis e permissões sejam necessários.

\section{Docker}
Segundo \citeonline{vitalino2018docker}, o Docker surgiu em 2013 a partir da empresa dotCloud, fundada por Solomon Hykes. Inicialmente, a empresa atuava com soluções PaaS (\textit{Platform as a Service}), permitindo suporte a diferentes linguagens de programação, diferentemente de outras plataformas da época.

Os autores destacam que o Docker nasceu como uma tecnologia open source baseada inicialmente em LXC (Linux Containers) e Union Filesystem, possibilitando a criação de containers leves e eficientes. Seu crescimento ocorreu rapidamente, tornando-se amplamente utilizado por empresas de grande porte, como Spotify, além de receber suporte de plataformas como AWS e Google.

De acordo com Vitalino e Castro (2018), o Docker trouxe maior facilidade na criação, distribuição e execução de aplicações em containers, garantindo mais portabilidade e consistência entre ambientes de desenvolvimento e produção. Além disso, por utilizar o mesmo kernel do sistema operacional hospedeiro, a tecnologia apresenta maior eficiência no consumo de recursos quando comparada às máquinas virtuais tradicionais.

Os autores também ressaltam que o Docker possui melhor desempenho em sistemas Linux, embora atualmente também possa ser executado em ambientes Windows e macOS. Dessa forma, o Docker tornou-se uma das principais ferramentas utilizadas em processos modernos de desenvolvimento e implantação de software.

\subsection{Testes automatizados de software}

O teste de software é uma atividade importante no processo de desenvolvimento, pois permite identificar falhas e avaliar se o sistema apresenta o comportamento esperado. Conforme discutido por \citeonline{sousa2023}, os testes podem ser realizados com o apoio de ferramentas de automação, que permitem executar verificações de maneira repetível e analisar o funcionamento de aplicações web.

A automação de testes utiliza scripts e ferramentas para reproduzir ações e verificar resultados previamente definidos. Essa prática pode contribuir para reduzir o esforço associado à repetição manual de testes, especialmente quando o sistema passa por alterações durante o desenvolvimento. Entretanto, os resultados obtidos dependem dos cenários definidos e não garantem, isoladamente, a inexistência de defeitos na aplicação.

\subsection{Testes de ponta a ponta (E2E)}

Os testes de ponta a ponta, conhecidos como E2E (\textit{End-to-End}), verificam o comportamento de uma aplicação a partir de fluxos completos de utilização. Em aplicações web, esses testes podem reproduzir ações realizadas pelo usuário no navegador e verificar se a aplicação responde conforme o esperado.

No estudo comparativo realizado por \citeonline{sousa2023}, o Cypress e o Selenium são analisados como ferramentas para automatização de testes em aplicações web. O trabalho aborda características como configuração, escrita dos scripts, recursos disponíveis e execução dos testes. Essa abordagem demonstra a importância de considerar tanto as funcionalidades das ferramentas quanto as necessidades específicas do sistema que será testado.

\subsection{Cypress}

O Cypress é uma ferramenta voltada à automação de testes de aplicações web. Segundo \citeonline{sousa2023}, a ferramenta utiliza JavaScript para a criação dos scripts de teste e foi projetada para trabalhar diretamente com a aplicação executada no navegador. Essa característica permite que os testes realizem ações na interface e verifiquem elementos e comportamentos apresentados durante a execução.

Entre as operações que podem compor um teste estão acessar uma página, localizar elementos, preencher campos, clicar em botões e verificar se o resultado esperado foi apresentado. A documentação oficial do Cypress também descreve recursos voltados à criação e execução de testes automatizados \cite{cypress2023}.

Outro aspecto discutido por \citeonline{sousa2023} é o mecanismo de espera automática do Cypress. A ferramenta pode aguardar que determinados elementos ou condições estejam disponíveis antes de concluir uma verificação, reduzindo a necessidade de configurar manualmente esperas em diversos cenários. Ainda assim, os testes devem ser planejados e implementados de acordo com o comportamento esperado da aplicação.

O estudo de Sousa (2023) também aponta que a escolha de uma ferramenta de automação deve considerar o contexto de uso. Embora o Cypress apresente facilidades na escrita e depuração dos testes, existem limitações em comparação com outras ferramentas, incluindo diferenças no suporte a linguagens, ambientes e determinados cenários de navegação. Portanto, sua adequação deve ser avaliada conforme os requisitos do projeto.

\subsection{Uso do Cypress no sistema FlashFood}

No sistema FlashFood, o Cypress pode ser utilizado para automatizar testes de ponta a ponta que verifiquem os fluxos implementados na aplicação. Entre os exemplos de cenários que podem ser avaliados estão a autenticação de usuários, a navegação pelas telas e as operações de gerenciamento de produtos, vendas e pedidos, desde que esses fluxos estejam implementados e façam parte dos testes desenvolvidos.

Em cada cenário, o teste deve executar as ações previstas e verificar se os resultados correspondem ao comportamento esperado. A execução repetida desses cenários após alterações no código pode auxiliar na identificação de regressões. Contudo, as conclusões sobre a qualidade do sistema devem se limitar às funcionalidades e condições efetivamente verificadas pelos testes.



\section{Redis}

O Redis (\textit{Remote Dictionary Server}) é um banco de dados NoSQL em memória amplamente utilizado como sistema de cache, armazenamento de sessões, filas de mensagens e banco de dados chave-valor. Diferentemente de outras soluções de cache, o Redis oferece suporte a diversas estruturas de dados, como listas, conjuntos, hashes e conjuntos ordenados, além de permitir persistência opcional dos dados em disco.

Segundo \citeonline{redis2025}, o armazenamento dos dados diretamente na memória RAM reduz o tempo de acesso em comparação com sistemas que dependem de operações em disco, tornando o Redis adequado a aplicações que exigem alto desempenho.

Além disso, o Redis oferece mecanismos de expiração automática de chaves (\textit{Time To Live -- TTL}), permitindo que os dados armazenados sejam removidos automaticamente após determinado período, evitando inconsistências e desperdício de memória.

\subsection{Cache em Aplicações Web}

O cache é uma técnica utilizada para reduzir o tempo de resposta das aplicações, armazenando temporariamente informações frequentemente acessadas em uma camada de memória de alta velocidade. Dessa forma, evita-se a execução repetitiva de consultas ao banco de dados e outros processos computacionalmente custosos, contribuindo para a melhoria do desempenho e da escalabilidade dos sistemas.

Em aplicações web modernas, o uso de mecanismos de cache torna-se essencial principalmente em cenários com elevado número de acessos simultâneos. A utilização dessa estratégia reduz a carga sobre o banco de dados, diminui a latência das requisições e melhora a experiência do usuário.



\subsection{Redis como Camada de Cache}

O Redis é frequentemente utilizado como uma camada intermediária entre a aplicação e o banco de dados. Quando uma informação é solicitada, a aplicação verifica inicialmente se ela está armazenada no cache. Caso esteja disponível, o dado é retornado imediatamente. Caso contrário, a informação é recuperada do banco de dados, armazenada no Redis e posteriormente enviada ao usuário.

\subsection{Escalabilidade Horizontal}

A escalabilidade horizontal consiste na ampliação da capacidade de processamento de uma aplicação por meio da adição de novos servidores, em vez do aumento da capacidade de um único equipamento. Nesse cenário, soluções de cache como o Redis desempenham papel fundamental, reduzindo o número de acessos simultâneos ao banco de dados e distribuindo de forma mais eficiente a carga entre os servidores.

Segundo \citeonline{sabbag2025}, arquiteturas que utilizam cache podem responder mais rapidamente às requisições dos usuários, proporcionando maior disponibilidade e desempenho.

\subsection{Aplicação do Redis no Sistema Desenvolvido}

Neste trabalho, o Redis foi utilizado como mecanismo de cache da aplicação desenvolvida em Laravel. Informações frequentemente consultadas, como listas de funcionários, categorias e outros registros de baixa frequência de alteração, foram armazenadas temporariamente no Redis utilizando o mecanismo \texttt{Cache::remember()} disponibilizado pelo framework.

Quando ocorre alteração nos dados, como inclusão, edição ou exclusão de registros, o cache correspondente é invalidado por meio do método \texttt{Cache::forget()}, garantindo que as informações apresentadas aos usuários permaneçam consistentes.

Essa estratégia reduz a quantidade de consultas ao banco de dados MySQL, melhora o tempo de resposta da aplicação e aumenta sua capacidade de atender múltiplos usuários simultaneamente.
